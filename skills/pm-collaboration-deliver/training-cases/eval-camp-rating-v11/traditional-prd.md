# 训练营满意度评价体系重构

> 需求依据：[03-PRD-评审稿.md](../../../交付产物/0617满意度评价体系重构/03-PRD-评审稿.md)。本文在不改动已确认业务规则的前提下，补全跨端页面流转、状态分支与后台操作表达。

## 1. 需求背景

训练营评价目前依赖 APP 既有入口和被动弹窗。旧流程先收集总体评价，部分用户再进入细项评价；H5 和小程序也缺少统一的新表单口径。由于 APP 升级不可控，旧版与新版评价会在一段时间内并行存在。

后台当前能够查询训练营评价，但缺少稳定的新旧表单标识、结营时间和实际接待人信息。运营、管理和数据人员难以判断一条记录采用什么口径，也无法稳定按实际服务归属查询和导出。

本期需要在不改变现有 APP 入口和触发条件的前提下，统一新版评价结构，兼容旧版提交，并保证同一学员在同一训练营只有一条当前有效评价。

## 2. 需求目标

- 新版 APP、H5 和小程序使用同一套四维五分制评价，提交结果可以跨端稳定解释。
- 旧版评价可以平稳迁移到新版，但新版形成后不再被任何渠道修改。
- 首次评价、旧评替代和重复提交不会造成多条有效评价或重复发放学分。
- 后台可以按照评价时间、结营时间、表单版本和实际接待人查询、解释并导出评价结果。

## 3. 需求范围

| 本期包含 | 本期不包含 |
|---|---|
| 新版 APP、H5、小程序四维评价表单 | 调整 APP 评价入口和被动弹窗触发条件 |
| 旧版 APP 兼容、旧评单次替代、新评永久锁定 | 批量迁移或重算历史评价 |
| 首次评价 80 学分联动及防重复约束 | 修改积分基础规则或低分人工服务规则 |
| 后台筛选、结果列表和导出字段升级 | 班主任邀评 SOP、回收率和绩效规则 |
| 新旧表单口径、结营时间和接待人展示 | 班主任绩效工作台、新版综合满意度 |

## 4. 产品方案

旧版 APP 继续进入旧表；新版 APP、H5 和小程序直接进入四维五分制表单。每次打开和提交时，系统都以当前有效评价版本为准：没有评价时可以首次提交，只有旧评时允许新版替代一次，已有新版评价时所有渠道均停止修改。

后台继续沿用现有训练营满意度页面，在筛选和结果中补充双时间、表单版本与实际接待人信息。新旧评价按各自口径展示，不互相换算。

## 5. 需求详情

### 5.1 新版入口直接填写四维评价

符合既有评价资格的用户通过新版 APP、H5 或小程序进入后，在同一表单中完成课程内容、老师讲解、班主任服务和画面质量四项评分。页面不再展示独立总体评价。

![目标态新版评价填写状态](form-states.png)

| 页面内容 | 规则 |
|---|---|
| 四项评分 | 每项均为 1–5 分，四项全部必填 |
| 分值语义 | 沿用现有五档语义：不满意、一般、符合预期、很棒、超预期 |
| 低分原因 | 单项选择 1–3 分时，在该项下展示已有负向原因；允许多选但不阻塞提交 |
| 改回高分 | 单项改为 4–5 分时，清除该项已选原因；其他维度不受影响 |
| 文字反馈 | 始终选填 |
| 提交按钮 | 四项全部完成后可用；提交过程中不可重复点击 |

低分原因文案沿用现状：

| 维度 | 原因标签 |
|---|---|
| 课程内容 | 没效果/没学会、实操案例不够、课程太长 |
| 老师讲解 | 速度太快、讲解不够细致、教学方式单一 |
| 班主任服务 | 沟通令人不适、回复很慢、频繁发消息 |
| 画面质量 | 卡顿、不清晰、没声音 |

### 5.2 旧评只允许被新版替代一次

“新评替代旧评”仅用于版本迁移，不是开放修改评价。一旦形成新版评价，旧版和新版入口均不能再次改变结果。

| 当前有效评价 | 提交来源 | 结果 | 学分 |
|---|---|---|---|
| 无评价 | 旧版 APP | 形成旧版评价，之后仍可被新版替代一次 | 首次按现有规则发放 |
| 无评价 | 新版 APP、H5、小程序 | 形成新版评价并永久锁定 | 首次按现有规则发放 |
| 旧版评价 | 新版 APP、H5、小程序 | 原记录完整更新为新版；旧内容不保留 | 不重复发放 |
| 旧版评价 | 旧版 APP 重复提交 | 保持原旧版评价 | 不发放 |
| 新版评价 | 任意入口 | 保持当前新版评价并展示已评价反馈 | 不发放 |

提交时必须重新判断当前有效评价，不能仅使用打开页面时的结果。多端同时提交时，最多一个请求形成最终有效结果；新版成功后，晚到的旧版提交不得覆盖新版。

### 5.3 提交结果与失败恢复

![目标态评价提交结果与恢复](submit-states.png)

首次形成有效评价时，沿用现有成功反馈和 80 学分规则。新版替代旧评成功时，展示既有提交成功反馈，但不再次发放学分。命中现有低分结果规则时，继续展示既有人工联系反馈，本期不改变触发阈值、文案和服务流程。

提交失败时，页面保留本次评分、原因标签和文字反馈，按钮恢复后允许重新提交。失败不得产生有效评价或积分；如果第一次已经成功但响应丢失，重试应收口为成功或已评价，积分仍只能到账一次。

替代写入失败时，原旧版评价必须保持完整有效；不能出现旧版总体评价和新版四维评分混合的中间结果。

### 5.4 后台按新旧口径查询和导出

有既有权限的后台用户继续在“运营管理—满意度—训练营满意度”中查询评价。页面沿用现有结构，补充结营时间、接待人和表单版本等筛选与展示能力。

![目标态后台查询与导出](admin-states.png)

| 项目 | 调整后规则 |
|---|---|
| 评价时间 | 沿用当前有效评价的提交时间，支持范围查询 |
| 结营时间 | 增加训练营结营时间范围；与评价时间组合时取交集 |
| 表单版本 | 明确区分旧版和新版，便于解释字段口径 |
| 新版总体评价 | 为空，不计算四项平均；按总体评价筛选时不命中任何分值 |
| 旧版评价 | 保留原总体评价和旧表细项，不转换为新版口径 |
| 接待人 | 接待表优先，延期用户表兜底；均无结果时为空或统一显示“未匹配” |
| 销售归属人 | 作为独立字段保留，不用于替代接待人 |
| 导出 | 字段和记录范围必须与当前筛选条件、列表口径一致 |

查询失败时保留筛选条件，允许重新查询。导出失败不改变评价数据和筛选条件，用户可以重新发起导出。

## 6. 通用规则与异常

- 新版总体评价始终为空，不以四项平均值补写；旧版总体评价保持原值。
- 首次有效评价最多发放一次 80 学分；旧评替代、重复提交、晚到提交和失败重试均不能再次发放。
- 资格、训练营信息或当前评价状态无法确认时，不允许写入评价，沿用既有异常反馈。
- 接待人缺失不阻塞其他评价查询，不猜测归属，也不使用销售归属人代替。
- 后台权限沿用现有满意度权限，不扩大未授权人员的数据范围。

## 7. 影响与上线

新版 H5、小程序表单、新版写入规则和后台展示需支持独立灰度。先在内部或测试训练营验证，再小范围开放 H5、小程序，确认评价写入、旧评替代、积分和后台结果后逐步放量；新版 APP 随正常发版覆盖。

旧版 APP 继续运行，不批量迁移历史数据。暂停放量的关键情形包括：新评被旧评覆盖、同一资格出现多条有效评价、重复积分、替代产生半更新记录，或后台新旧口径展示错误。

回滚不能删除已经成功的新评，也不能把已经替代的记录恢复成可以再次获得评价积分的旧评。具体开关、监控、补偿和数据回滚步骤进入研发方案。

## 8. 验收标准

- 新版 APP、H5 和小程序直接展示四维五分制，不再出现独立总体评价。
- 四项未完成时不能提交；单项低分原因可多选且非必填，改高分后清除该项原因。
- 无评价时首次提交形成唯一有效评价；有旧评时新版可以完整替代一次；形成新版后所有入口永久停止修改。
- 多端并发、重复点击和弱网重试不会产生多条有效评价，也不会重复发放 80 学分。
- 提交失败保留全部输入，且不产生有效评价或积分；替代失败时原旧评保持完整。
- 新版记录展示四维评分、总体评价为空；旧版记录保留原总体评价和旧表口径。
- 评价时间与结营时间组合查询取交集；接待人按已确认优先级返回，未匹配结果可以识别。
- 列表与导出使用同一筛选范围和字段口径；查询或导出失败均可在保留条件的情况下重新操作。
