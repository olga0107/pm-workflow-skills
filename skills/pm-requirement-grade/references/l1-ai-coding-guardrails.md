# L1 AI Coding 自助边界

> 定位：本文件定义 L1 AI Coding 自助的**准入条件和最小上线门禁**，不替代项目代码规范、Code Review 或安全审查。

## 必须同时满足

1. 需求目标清楚，能用 3-5 条可验收标准说清楚。
2. 改动范围清楚，最好限制在一个页面、一个局部模块或一个私有组件内。
3. 不改变资金/交易、登录/授权/隐私、权益/资产、核心链路、状态机或数据归属。
4. 不新增后端写入、数据补偿、生产数据处理或长期用户资产。
5. 不新增依赖、SDK、生产域名、WebView/外链或基础设施配置。
6. 不处理用户敏感信息，不读取/记录 token、手机号、地址、证件号等。
7. 不触及共享基础组件；如触及共享组件，必须证明仅当前页面使用，否则至少 L2。
8. 产品/业务方能完整自测，包括主路径、返回、刷新、空态、异常态、不同权限/登录态（如适用）。
9. 出问题可以通过 revert、关闭入口、配置隐藏或回滚发版快速恢复，且不需要数据/权益/资金补偿。
10. 项目画像中未命中更高等级红线。

## 最小上线门禁

1. 分级卡确认 L1，且没有待确认高风险项。
2. Diff 白名单：说明改了哪些文件，为什么只影响这些文件。
3. 禁止项复核：无新增依赖、无生产域名/SDK、无敏感硬编码、无 mock/测试数据进生产、无吞异常导致假成功。
4. 构建通过：执行项目对应 build 命令；没有脚本时说明原因和替代验证。
5. Lint/格式化：至少对变更文件执行 eslint/prettier/类型检查，或说明项目暂无对应脚本。
6. 本地/目标平台自测：覆盖主路径、异常/空态、返回/刷新、不同登录/权限态、主要机型/字号。
7. 人审 AI diff：确认没有越权改动、核心判断变化、安全风险或兼容性风险。
8. 留档：截图或录屏、自测记录、构建结果、变更范围。
9. 回滚：说明回滚 commit/分支、关闭入口、配置恢复或发版回滚方式。
10. 上线观察：错误、投诉、关键页面访问/点击、相关转化或业务指标。
