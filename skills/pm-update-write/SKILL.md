# pm-update-write

把已确认变化转换成便于知晓、执行或追踪的更新材料。

本 skill 只转换和传播已确认事实，不负责补做需求定义、改变产品方向或替代 PRD；输入存在冲突时先返回对应决策或交付文档确认。

## 优先读取

1. [更新说明模板](./references/更新说明模板.md)
2. 已确认的 PRD、决策记录、版本计划或上线结论
3. 与目标受众相关的规则、运营和执行文档

规则、指标、角色关系或结算改造时，另读[需求迭代闭环与收尾协议](../../shared-references/需求迭代闭环与收尾协议.md)，只取已确认的变更台账和收尾状态。

## 输入检查

开始前至少确认：

- 本次同步目的：知情、确认、决策、执行或留档
- 目标受众及其需要采取的动作
- 已确认的来源文档、版本、范围和生效时间
- 新旧差异、明确不变项、风险和待确认事项
- 交付状态、发布状态、发布版本 / 日期和文档同步状态是否分别可确认
- 稳定知识、需求包、PRD / HTML、验收记录和实际实现之间是否存在状态或旧口径冲突

如果背景、规则、范围或时间仍存在会改变产品决策的冲突，先回到 `pm-requirement-define` 或 `pm-prd-write`，不要用更新文案掩盖未决结论。

## 选择输出类型

### 更新说明

用于解释为什么更新、改了什么、影响谁、何时生效以及需要做什么。

### 变更通知

用于原计划、范围、规则或时间发生变化时，明确新旧差异、原因和行动项。

### 更新日志

用于按版本或日期记录新增、调整、修复、下线和已知限制。面向用户时避免技术提交语言；面向内部时可补充影响模块和负责人。

## 工作流程

1. 明确同步目的：知情、确认、决策、执行或留档。
2. 确认受众及其最关心的目标、操作、风险和时间。
3. 从已确认材料中提取背景、变化、不变项、影响和证据。
4. 将未确认项与既定结论分开，不擅自补全。
5. 明确生效范围、时间、负责人、截止时间和资料入口。
6. 按输出类型控制篇幅和表达，不照搬整份 PRD。

## 规则迭代与状态对账（命中时执行）

对已有规则 / 结算 / 角色关系的迭代，先以需求迭代协议中的规则变更台账和交付闭环表为边界，做一次状态对账：

1. 对照已确认 PRD、实现记录、验收清单和稳定知识，找出仍保留旧口径或旧状态的材料；
2. 分开记录：交付状态（方案中 / 实现中 / 待验收 / 已验收 / 已归档）与发布状态（待发布 / 已发布 / 无需发布 / 不适用）；
3. “已验收”只能说明用户 / 测试验收完成；只有明确生产发布确认才能写“已发布”，发布版本和日期未知时写“待补充”；
4. 更新说明必须列出发布前动作、发布后观察、历史数据边界、已知限制和责任人，不把测试环境验证写成生产已上线；
5. 若来源之间存在冲突，先返回冲突和需要确认的上游，不用文案替读者做产品或发布决策。

## 与其他 skill 的关系

- 从 `pm-requirement-define` 获取已确认的问题、方向、范围和取舍。
- 从 `pm-prd-write` 获取已确认的功能、规则、发布、验收和兼容信息。
- 需要判断上线效果或异常原因时转给 `pm-metrics-review`，不在更新说明中自行解释因果。
- 更新材料只传播既有结论，不重新做产品方向选择，也不替代技术提交日志。

## 质量门禁

本 skill 的“完成标准”只表示产物已按方法生成，不等于已通过交接质量审计。

- 讨论、探索或用户明确要求“只先给初稿”时，不自动审计，并明确标记“未审计”；
- 当输出达到 `ready`、给出最终分级、准备交给设计 / 研发 / 测试 / 运营，或用户要求复核 / 验收时，必须在本次交付前自动调用 `pm-quality-audit`；
- 只有 `PASS`，或用户明确接受带责任人和完成条件的 `PASS_WITH_CONDITIONS`，才可标记为可交接；
- `BLOCKED` 必须回到本 skill、证据 skill 或上游决策，不得用补造事实的方式消除；
- 是否需要把审计报告写入项目根目录 `quality-audits/`，按用户是否要求留档 / 交接附件决定。

## 默认输出

1. 标题与一句话结论
2. 更新背景与目标
3. 新增、调整、修复、下线或计划变化
4. 明确不变项
5. 影响范围、生效时间和兼容说明
6. 需要相关方执行或确认的事项
7. 风险、已知限制和待确认项
8. 相关资料、负责人和反馈入口

## 完成标准

- 标题和开头能直接看出更新内容与目的
- 新旧差异、影响对象和生效时间无歧义
- 行动项包含负责人、结果和时间
- 已知限制与未确认信息明确标记
- 更新日志按统一分类和时间顺序组织
- 文案符合目标受众，不使用无必要的技术术语
- 规则迭代已完成来源对账；交付状态、发布状态、历史边界和文档同步状态未混写；
