# L3 高风险需求评审清单

> 定位：本清单是 L3 高风险需求的**评审门禁检查表**，用于确认 PRD、研发 spec、测试方案和发布治理是否齐备；它不定义 PRD 章节、写作深度或正式模板。
>
> PRD 的内容标准、章节裁剪、PRD/spec 边界和验收矩阵以 `pm-prd-write` 及其 `references/PRD模板.md` 为准。本清单只检查“是否覆盖高风险交付所需事项”。

## 1. PRD

以下只检查 PRD 是否覆盖 L3 门禁重点；具体写法、章节和验收矩阵以 `pm-prd-write` 为准。

- [ ] 问题、目标、非目标清楚，并能追溯到需求定义。
- [ ] 主路径、历史路径、页面/模块、状态、权限、异常、数据边界清楚。
- [ ] 影响范围、不兼容项、迁移/补偿项清楚。
- [ ] 灰度、回滚、降级策略清楚。
- [ ] 验收标准和上线观察指标清楚。
- [ ] 若体验交付复杂度为“复杂”，PRD 已按命中信号覆盖页面地图、状态架构、复杂组件行为、端与布局矩阵和原型覆盖计划；该项不替代 L3 风险门禁。

## 2. 研发 spec / 技术方案

- [ ] 涉及系统、接口、数据、状态机、异步任务已评审。
- [ ] 资金/权益/登录/隐私/核心链路/AI 自动化等关键风险已逐项处理。
- [ ] 幂等、重试、超时、失败兜底、数据一致性、审计可追溯已说明。
- [ ] 生产配置、开关、监控、告警已说明。
- [ ] 回滚、降级和数据/权益/资金补偿预案已说明。

## 3. 测试方案

- [ ] 主路径用例。
- [ ] 历史路径回归。
- [ ] 异常态和边界态。
- [ ] 权限/权益/登录态。
- [ ] 数据一致性、重复操作、并发/弱网。
- [ ] 多机型/浏览器/版本兼容。
- [ ] 灰度和回滚验证。

## 4. 发布

- [ ] 开关粒度和默认状态。
- [ ] 灰度范围、放量节奏、暂停/回滚条件。
- [ ] 回滚责任人和操作步骤。
- [ ] 上线观察指标和观察周期。
- [ ] 事故联系人和升级路径。
- [ ] 上线公告、客服/运营口径（如适用）。
