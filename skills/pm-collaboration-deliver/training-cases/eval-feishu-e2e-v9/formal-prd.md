# APP 排课冲突提醒与用户自主换期｜正式规格源

## S1 范围与责任

- 本期仅覆盖 APP。
- 用满负责冲突计算、阈值、触发判断、同一冲突关系去重和唯一候选期筛选；C 端不参与上述业务判断。
- 用满决定触达后，向 C 端提供两门冲突课程、冲突时间、被调整课程、当前安排和唯一调整后安排等完整信息。
- C 端负责同时生成 Push 与站内消息、新增自主换期页面、提交 CRM、展示成功结果或统一拦截结果。
- CRM 负责真实执行用户自主换期；用户端发起时免审批。换期前后班主任不变。

## S2 正常主流程

用满发送有效触达结果后，C 端同时生成 Push 和站内消息。用户点击任一入口时，系统重新校验当前方案；有效则进入新增“调整上课时间”页。页面展示具体冲突课程、冲突时间、当前安排和唯一调整后安排，并说明“本次仅可自主调整一次，调整后班主任不会改变”。用户二次确认后提交 CRM；只有 CRM 明确成功时才展示“课程已调整成功”。

## S3 页面与文案

### Push

- 标题：您的课程时间有重叠
- 正文：您报名的两门课程上课时间有重叠，可前往查看并调整上课安排。

### 站内消息

- 标题：课程时间调整提醒
- 正文：您报名的「课程 A」和「课程 B」上课时间有重叠。我们为您找到了一个可调整的上课安排，您可以进入查看。
- 按钮：查看调整方案
- 消息保留；用户关闭 Push 时仍可从站内消息进入。

### 调整上课时间页

- 展示两门冲突课程、冲突日期和时间段。
- 展示被调整课程的当前安排和唯一调整后安排。
- 说明：请确认新的开课时间适合您。本次仅可自主调整一次，调整后班主任不会改变。
- 主按钮：确认调整。
- 次按钮：暂不调整。点击后不提交换期，课程安排不变，站内消息继续保留。
- 二次确认弹窗按钮：确认调整、我再看看。

### 成功页

- 标题：课程已调整成功。
- 正文：展示被调整课程和新的开课日期，并说明班主任不会改变。
- 按钮：查看学习日历；次按钮为返回首页。

### 拦截页

- 标题：暂时无法在线调整。
- 正文：当前课程安排暂时无法在线调整。如需更换上课时间，请联系您的班主任协助处理。
- 主按钮：联系班主任；次按钮：返回学习日历。
- 所有业务拦截、方案失效、信息缺失、请求失败、超时或结果不明确均进入该页面，不提供在线重试。

## S4 状态与异常

- 每次打开 Push 或旧站内消息都重新校验，不能使用消息生成时的历史资格直接放行。
- 已自主换期、后台已换期、退款、转课、无听课权限、存在待处理流程、目标期失效或当前资格无法确认时，统一进入拦截页。
- 提交期间禁止重复点击；重复请求不得产生多次换期。
- 未收到 CRM 明确成功结果时不得展示成功页。
- “联系班主任”进入现有班主任联系入口；如果没有有效入口，降级至现有统一客服。

## S5 数据、兼容与发布

- 本期不新建独立业务埋点或数据看板，优先复用消息平台、用满和 CRM 已有记录；必须保留支持单用户问题排查的必要日志。
- 研发需验证在用 APP 版本能否打开新增页面；不支持时不得生成无法打开的入口，具体降级方式由研发方案确定。
- C 端需具备关闭消息生成、新增入口和 CRM 提交的降级开关。
- 已成功换期的数据不自动回滚，异常时由 CRM 和业务人工处理。

## S6 验收底线

- 一次有效触达同时生成 Push 和站内消息。
- 两个入口均在重新校验后进入同一调整页面或统一拦截页。
- 页面信息完整、只展示一个方案，并明确一次自主调整及班主任不变。
- 暂不调整不修改课程，站内消息保留。
- CRM 明确成功后才展示成功；失败不支持重试，只联系班主任。
- 重复点击或并发请求不能产生重复换期。
