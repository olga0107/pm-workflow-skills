# pm-quality-audit

对一份已生成的产品工作产物做独立质量审计，而不是继续润色正文。

## 使用方式

1. 指定审计对象、阶段、输入版本和预期下游。
2. 读取共享质量框架、原 skill、模板、上游来源和项目规则。
3. 建立上下文充分性账本：区分 confirmed、inferred、assumed、unknown、blocked。
4. 对逻辑、遗漏、矛盾、过度确定、下游可执行性和追溯关系做对抗式检查。
5. 输出 Blocker / Major / Minor 缺陷、证据定位和 PASS / PASS_WITH_CONDITIONS / BLOCKED。
6. 如用户要求修复，先保留审计发现，再回到原 skill 修复，最后只复审受影响范围。
7. 默认在对话中返回报告；用户说“留档”或“作为交接附件”时，将报告写入当前项目根目录 `quality-audits/`。

默认不要为了让文档通过而补造事实；信息不足时应明确阻塞或补证据路径。讨论 / 初稿可以跳过审计，但必须标记“未审计”，不能宣称可交接。

## 常用协作表达

```text
先审计刚才的需求定义，不要修改原文。

审计并修复刚才的 PRD，先列问题，再修复，最后复审。

把本次质量审计报告留档，作为研发交接附件。
```
