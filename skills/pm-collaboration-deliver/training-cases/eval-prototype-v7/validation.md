# pm-collaboration-deliver 原型能力验证 v7

## 验证目标

验证 Skill 是否能把原型工作拆成“输入证据—设计语义—视觉执行—交付验证”，并在不补造产品规则的前提下承接正式 PRD、现状截图、已确认设计或无视觉资产场景。

## 场景与结果

| 场景 | 预期 | 结果 |
|---|---|---|
| 正式 PRD 交互语义完整、无视觉资产 | 允许生成聚焦故事板，并校验状态与迁移 | 通过；下载案例计划覆盖 4 个状态和 3 条连续迁移 |
| 只有零散 PRD 和现状截图 | 只允许标注现状和列未知，不允许生成完整交互 | 通过；标注计划通过 |
| 截图直接生成成功故事板 | 必须被阻止 | 通过；同时命中语义不足、缺正式 PRD 行为证据、缺交互模型 |
| 已确认设计却重新画低保真 | 除非显式说明复用例外，否则阻止 | 单元测试通过 |
| 故事板引用不连接所选状态的迁移 | 必须被阻止 | 单元测试通过 |
| 连线穿过非目标页面 | 必须在渲染阶段阻止 | 首轮真实渲染发现；已增加硬门槛和回归测试 |

| 聚焦任务故事板 | 步骤、动作、进度、成功/失败分支可读 | 两张 SVG/PNG 通过并实际查看 |

## 多轮返工记录

### 第一轮：输入与设计权限

建立产品语义充分度、视觉上下文充分度和证据角色。正例计划通过，截图越权生交互的反例被拦截。

### 第二轮：截图执行

使用真实满意度浮层截图生成编号标注图。实际查看发现说明文字的句号可能孤行，已修正中文换行规则并重新渲染。

### 第三轮：故事板执行

增加步骤编号和通用进度组件。首次结果分支横排时，“下载中 → 下载失败”连线穿过“已完成”页面并压住按钮。已把连线穿越非目标页面改为渲染硬错误，并将分支改成上游状态居中、两个结果下沉的拓扑；复看后主线和分支均清楚。

## 成熟度判断

| 能力 | 当前判断 | 证据与边界 |
|---|---|---|
| 承接上游 PRD | 强 | 明确消费 Page / IA / State / Action / Transition，并按充分度限制输出深度 |
| 产品规则保护 | 强 | 截图不能单独授权行为；行为原型必须有正式 PRD 证据；迁移必须连接所选状态 |
| 截图承接 | 中强 | 已有登记、观察/推断/未知、敏感信息检查、编号标注和真实渲染；元素识别仍由 AI 视觉检查完成，不虚称全自动 OCR |
| 原型设计方法 | 中强 | 已覆盖信息层级、主次操作、反馈邻近、关键帧和复用策略；高保真视觉仍依赖已确认设计系统或设计稿 |
| 低保真执行 | 中强 | 支持通用页面块、步骤、进度、动作连线、目标宽度门槛和页面穿越检查；复杂图仍需按读者问题拆分和人工复看 |
| 交互完整性 | 强 | 完整模型与聚焦展示分离，状态、动作、迁移和可达性已有独立检查 |
| 最终阅读验证 | 强 | 要求正文宽度、放大视图、实际资产和无上下文读者检查 |
| 飞书适配 | 本轮未重测 | 原型方法与飞书发布解耦；实际飞书画板和正文回看继续由发布路径负责 |

## 结论

本轮补全的重点不是让 Skill 自由设计更多，而是让它知道“依据什么设计到哪一层”，并把截图、页面设计、连续交互和渲染质量纳入同一闭环。当前已从“能画页面状态”提升为“能判断设计权限、选择正确原型形式、生成可读资产并抓住常见错位”的可复用能力。

仍不应宣称替代最终 UI 设计：没有已确认设计系统时输出的是产品结构示意；需要高保真时，应承接现有 Figma / 设计资产并在对应工具中继续设计，而不是让低保真渲染器冒充视觉定稿。
