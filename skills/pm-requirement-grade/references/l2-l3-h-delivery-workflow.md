# L2/L3/H 协作流程与交付物决策

> 定位：本文件定义 L2/L3/H 的**协作流程和门禁要求**，不展开正式 PRD、研发 spec、测试方案或复盘报告。需要完整文档时转对应 owner 或 skill。

## L2 中风险协作需求

适用：影响已有页面、共享组件、已有接口展示或历史路径，风险可控，不触及资金、身份隐私、权益资产、核心链路、后端状态写入、全局配置、外部依赖等 L3 红线。

最低流程：

1. 产品输出 L2 协作简报；若需求范围跨多页面、多角色、状态 / 权限 / 规则复杂，转 `pm-prd-write` 输出评审简版或 PRD。
2. 研发做影响面评估，确认没有误触 L3，并判断是否需要研发 spec。
3. 设计确认视觉、交互、可访问性/适老化和边界态。
4. 测试覆盖主路径、历史路径、异常态、兼容机型/浏览器。
5. 至少 1 名研发 Code Review。
6. 上线后观察 1-3 天，视影响面决定是否灰度。

体验交付复杂度独立于 L2 / L3 / H 风险等级。分级标记为“复杂”时，PRD 仅按命中信号补充页面地图、状态架构、组件行为、端与布局矩阵和原型覆盖计划；如果目标是在设计前评估完整页面效果，额外标记“内容完整型 UX 原型”，由 PRD 建立页面内容契约和页面 × 状态 × 内容覆盖；需要视觉协作评审时，再由 `pm-prd-html` 将这些事实编译为单个 HTML 的代表状态和端形态，并执行内容覆盖检查，不改变 L2 的门禁或将其自动升为 L3。

## L3 高风险/核心需求

适用：资金、交易、权益、身份、隐私、生产数据写入、状态机、AI 自动化结果、核心链路、全局配置、外部依赖或不可快速回滚。

最低流程：

1. 完整 PRD：使用 `pm-prd-write`，本 skill 只提供风险重点和评审门禁。
2. 研发技术方案/spec 评审：系统边界、接口、数据、状态机、幂等、重试、失败兜底、审计、监控、开关、回滚。
3. 测试方案评审：主路径、历史路径、异常态、权限/权益/登录态、兼容性、弱网、重复操作、灰度和回滚验证。
4. 安全/合规/数据口径确认：按风险参与。
5. Feature Flag / 灰度策略：默认关闭、分层放量、放量条件和暂停条件。
6. 可观测指标和告警：错误率、核心路径转化、关键业务指标、投诉/客服反馈。
7. 回滚与降级方案：责任人、触发条件、操作步骤、数据/权益/资金补偿预案。
8. 上线后观察报告或复盘。

## H 线上紧急修复

适用：线上已发生或正在发生的问题，需要快速止血。

规则：

1. 禁止产品/业务方 AI Coding 自助修复后直接上线。
2. 先止血，再补测试、复盘和长期修复。
3. 涉及资金、权益、隐私、登录、播放、数据损坏或大面积不可用时，必须由研发/值班负责人判断。
4. Hotfix 治理包必须包含：问题时间、影响范围、触发条件、止血方案、验证结果、回滚/补偿、复盘 owner；不在本 skill 内替代事故复盘。
5. 修复后判断是否需要回到 L2/L3 正常流程补长期方案。
